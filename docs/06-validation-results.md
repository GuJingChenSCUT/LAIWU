# 分角色版本验证记录

日期：2026-10-11。应用 0.2.0，Windows、Node.js v24.19.0，本机端口 3100，默认 Mock 模式。

## 已通过的检查

- `node --test tests/*.test.mjs`：17 项通过，0 项失败。
- 模型接口：结构化请求与结果校验、拒答、格式错误、HTTP 错误和失败停止。全部使用本地 fetch 替身，不代表真实模型服务连通。
- 业务规则：角色不能代签其他范围、旧页面版本冲突、幂等请求、英文修改使其他签收失效、素材撤回与到期限制。
- 报价与样品：缺运费、税口径不一致、缺起算条件或过期时不计算总额；规格变更使旧报价失效；展示范围不能用于样品；返工需重新送验。
- 场次：新草稿期间仍可向开放的旧场次反馈，记录保留旧内容版本；窗口关闭后拒绝新增。
- 本地持久化基础：已有 JSON 存储重开测试覆盖修订保留和中断工作流恢复。

## 浏览器端到端

`node scripts/verify-business-ui.cjs` 使用 Playwright / Chromium，已完整通过：

1. 生成帆布袋提案，登记范围，文化和品牌分别签收。
2. 冻结规格，提交缺项报价，再提交完整示例。
3. 样品送验、记录返工、重新送验、演练接受。
4. 主播核对双语，建立场次，真人特效交互。
5. 相机不可用时保持舞台可演示；阻断 API 请求时本机停止按钮仍有效。
6. 观众反馈，修改中文，舞台重新锁定，旧场次反馈保留原版本。
7. 三方重签、新场次、品牌下一轮决定。
8. 页面刷新后恢复项目、工作视角和业务记录，交接包下载成功。
9. 1440px 桌面和 390px 手机布局；五个原有页面、五角色入口和品牌各工作区无横向溢出，未捕获 pageerror。

首次走查发现刷新后工作视角丢失，修复了标签页视角保存和工作区地址，再完整重跑通过。

## 尚未实现或验证

真实登录和组织数据隔离、真实模型网络、真实摄像硬件、外部直播停止回执、真实授权/供应商/样品/质检、进出口办理、支付和订单均不在本轮已验证能力内。

## 如何复跑

先启动服务。在已安装 Playwright 的环境运行 `node scripts/verify-business-ui.cjs`；如不在 Node 模块搜索路径，用 `PLAYWRIGHT_PATH` 指向现有模块目录。`scripts/verify-ui.cjs` 为相同检查的兼容入口。

检查会创建一个标记为演示的本机项目、报价、样品记录和观众反馈；这些都不是生产数据。
