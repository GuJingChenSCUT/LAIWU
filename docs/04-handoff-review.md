## 4. 現有工程運行邊界

所有業務操作限本機。服務端有 Host／Origin 檢查、靜態檔白名單、請求大小和同時生成數限制、模型逾時、輸出結構校驗、前端文字轉義及基礎 CSP。這些措施不是正式多租戶安全審計。

資料檔本機明文保存，適用虛構／非敏感演示資料。不要將它作公開服務直接使用。版本變更不會刪除舊修訂；挑戰資料只保存在記憶體，服務重啟需重新領取。

已完成或已確認的項目可以重啟恢復；執行中工作流標記失敗，不自動續跑。文件寫入採臨時檔＋替換，適合本機單進程；資料庫、備份、租戶權限和完整稽核是後續工作。

## 5. 下一個工程迭代，按證據排序

1. 實際訪談與一份付費試點的交付規格；確定第一個 SKU 和文化合作方。
2. 把三份真實、經同意的 brief 做成評估集：來源完整性、可用稿率、誤述率、核對和返工工時。
3. 若多人持續使用，加入登入、workspace 隔離與正式資料庫；保留狀態機和確認邊界。
4. 接通一個已確認可用的模型，驗證 JSON Schema／拒答／逾時／輸出品質／費用，再作現場主線。
5. 將已批准修訂變成品牌規則庫並測試是否减少重複錯誤。不要先開全量自動訓練。
6. 有真實觀眾與項目預算後再接既有直播渠道或 SDK；需要時才加付費、履約、售後與供應商資料。
